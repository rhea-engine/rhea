# Rhea v0.3.0: open and browse remote worlds

Rhea v0.3.0 is available on
[GitHub](https://github.com/rhea-engine/rhea/releases/tag/v0.3.0).

[Download Ceto v0.3.0 for Windows x64](https://github.com/rhea-engine/rhea/releases/download/v0.3.0/Ceto-0.3.0-windows-x64.zip).
Extract the complete ZIP and start `Ceto.exe`. The package includes the viewer,
runtime libraries, engine resources, and Courtyard example. See
[First steps with Ceto](../ceto-courtyard.md) for startup and controls.

## Remote worlds in Ceto

Ceto supports `http`, `https`, `file`, and `realm` addresses. Open a local world,
paste a direct HTTPS scene URL, or use a configured realm address. Remote worlds
load their dependent scenes and assets through Orion. Hosting can use a normal
static HTTP(S) server; direct scene loading does not require a catalog.

The Open Browser can navigate local directories and remote JSON catalogs.
A server can return a catalog for a directory URL or provide `index.json`.
Catalogs are identified by `"format": "orion-catalog"`, not a custom MIME type.
The required `version` is `1`, and `entries` is required but may be empty.
Entries use `directory`, `world`, or `file`, with a name and target reference.

Relative catalog links use the effective catalog address after redirects.
Directory URLs with and without a trailing slash, and explicit `index.json`
URLs, are supported. If a directory request returns HTTP 403, Ceto tries its
`index.json`; a blocked directory listing need not prevent catalog access.

See [Publish a scene for Ceto](../publishing-scenes.md),
[Remote Browsing Catalog](../browsing-catalog.md), and
[Realm Addressing and Resolution](../realm-addressing.md) for hosting and
addressing details.

## Validation

Manual acceptance checks confirmed:

- Opening a world from a local file, remotely through a realm, and through HTTPS.
- Browsing directory addresses ending in `worlds`, `worlds/`, and
  `worlds/index.json`.
- Correct resolution of relative catalog links.
- Correcting an invalid `index.json` and reloading it successfully in the same
  Ceto process.
- Falling back to `index.json` after HTTP 403 on a directory request.

The `0.3.0-rc1` ZIP was also executed successfully on a second Windows computer.
These are manual checks, not a claim of exhaustive transport, security, or
platform validation.

## Compatibility and known limitations

Rhea remains experimental; no stable API or resource-format compatibility
guarantee is introduced by this release. Rebuild applications against the
matching engine revision.

- The tested binary package targets Windows x64. This release's checks do not
  establish equivalent remote-workflow validation on Linux or macOS.
- The Windows package is unsigned. Windows may display an unknown-publisher or
  reputation warning. Public code signing remains follow-up work.
- Use trusted remote scenes. This release does not claim an audited sandbox
  for untrusted content.
- `file` catalog entries currently follow the same opening path as `world`;
  a separate generic-file action is not implemented.
- Cache/update behavior, resource limits, cancellation, and wider transport
  failure coverage remain follow-up validation topics. Reopening a world can
  reuse loaded resources; use a fresh process when checking published updates.

Further catalog implementation notes and open decisions are recorded in
[Remote Browsing Catalog](../browsing-catalog.md). Report reproducible problems
through the [engine issue tracker](https://github.com/rhea-engine/rhea/issues),
including the Ceto version, address, operating system, and relevant diagnostics.
